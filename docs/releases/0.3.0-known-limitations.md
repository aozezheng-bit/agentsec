# AgentSec 0.3.0 Known Limitations

AgentSec 0.3.0 is a local static-analysis and deterministic-policy internal MVP.
It does not prove that an Agent is globally safe.

## Runtime and framework limits

- Codex is the primary structured Framework Adapter;
- no runtime Tool enumeration, OAuth-scope attestation, identity proof,
  permission reachability, exploit execution, or active red-team validation;
- static Capability and vulnerability associations do not prove exploitability;
- no general multi-framework production support.

## Detection and calibration limits

- deterministic Rules can miss semantic, novel, or framework-specific behavior;
- P2-30 Pilot evidence is curated `internal_integration` evidence;
- six Markdown Rules lack positive Pilot scenarios and remain `more_data`;
- Pilot Precision/Recall must not be generalized to production;
- scoring replay proves deterministic stability, not financial-loss accuracy;
- no LLM semantic analysis or automatic Rule publication is included.

## Policy limits

- default behavior remains report-only;
- Organization Policy and Waivers are local unsigned files;
- Waivers have no remote approval service, signature, or centralized lifecycle;
- `--fail-on critical` is supported, but current static Markdown profiles do not
  inflate static declarations to Critical without reviewed likelihood evidence;
- Capability enforcement currently supports the qualified
  `HG-CAPCHAIN-001` path rather than arbitrary user-defined Gates.

## Artifact and product limits

- local SHA-256 establishes consistency, not author identity or freshness;
- no Web console, remote policy service, organization dashboard, or package
  registry publication;
- no Git commit, tag, signed source provenance, SBOM signature, or SLSA claim;
- reports may contain sensitive metadata even though recognized Secret values
  and source excerpts are minimized or redacted.

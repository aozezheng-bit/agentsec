# AgentSec 0.2.0 Release Notes

- Release date: 2026-08-20
- Release type: local Phase 2 Integration MVP
- Status: Accepted locally after Hardening / Release Review

## Purpose

AgentSec 0.2.0 adds a deterministic structured capability-analysis product path
to the accepted Phase 1 Markdown scanner. It can build a source-backed Agent
Manifest, assess structured capability combinations, compare saved Manifest
states, and present a bilingual Capability Drift story without executing scanned
content.

## Command surface

Existing Phase 1 commands remain:

```text
agentsec version
agentsec scan
agentsec baseline create
agentsec diff
agentsec rules list
```

New Phase 2 commands:

```text
agentsec manifest
agentsec capability assess
agentsec capability diff
agentsec capability rules list
```

## Highlights

- bounded JSON, YAML, TOML, Codex `.rules`, and static MCP parsing;
- non-executing Codex Framework Adapter with explicit roots and Coverage;
- Agent Manifest Schema `0.3.0` with instructions, configuration, tools,
  permissions, controls, runtime identities, relationships, Unknowns, and
  provenance;
- deterministic instruction/configuration resolution and capability extraction;
- Capability Diff Schema `0.1.0` with value-minimizing fingerprints and source
  references;
- Capability Rule Pack and Risk Model `0.1.0` with six bilingual combination
  Rules;
- Capability Assessment Output `0.1.0` with management summary, Findings, Stage
  Trace, Rule failures, and fixed report-only policy;
- English and Simplified Chinese Manifest, Assessment, and Diff Text;
- bounded Manifest input and private atomic report Artifact output;
- bilingual live/offline Capability Drift Demo with SHA-256-frozen output;
- hardening for validation field-path disclosure and no-follow replacement reads.

## Policy

```text
enforcement_mode=report_only
ci_blocking_enabled=false
runtime_capability_verified=false
global_safety_claimed=false
```

Complete analyses return `0` even when Findings exist. Incomplete Coverage or
Rule execution returns `2`. Invalid or unsafe artifacts return `4`. Exit `1`
remains reserved.

## Distribution boundary

The local candidate is stored under `dist/0.2.0/` so the accepted 0.1.0 files
remain preserved. This workspace is not a Git repository and has no configured
remote publication target. No tag, signed commit, PR, package-index upload, or
production deployment is claimed.

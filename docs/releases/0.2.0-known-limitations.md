# AgentSec 0.2.0 Known Limitations

AgentSec 0.2.0 is a static, local, report-only Phase 2 Integration MVP. It does
not prove that an Agent is globally safe or that a declared capability is
reachable at runtime.

## Input and framework limits

- production Framework mapping is currently Codex-focused;
- file discovery and semantics cover reviewed Codex Agent, Skill, Rules, TOML,
  and static MCP declarations, not every framework or proprietary format;
- parsers do not follow include/import/reference fields;
- external MCP tools are not connected or enumerated at runtime;
- user-home and Codex-home inspection roots must be supplied explicitly.

## Analysis limits

- static permission, control, and runtime identity facts are hypotheses backed by
  declarations, not attestations;
- Capability Diff reports changed fields, hashes, and provenance rather than raw
  before/after values;
- Capability Change Impact / Finding Delta from original P2-13 is not complete;
- Capability Rule Pack contains six Rules, not the planned 20–30 P2-14 Rules;
- no production Capability Hard Gate is active; every Capability Finding has
  `hard_gate=false`;
- Agent-wide delegation and persistence correlations remain D Confidence when
  target manifests/data flow are unresolved;
- Unknowns and CAP-COVERAGE-001 may remain even with complete file Coverage;
- no LLM semantic analysis, attack graph, dynamic red-team execution, or runtime
  validation is included.

## Policy limits

```text
enforcement_mode=report_only
ci_blocking_enabled=false
runtime_capability_verified=false
global_safety_claimed=false
```

- no `--fail-on`;
- no CI risk blocking;
- no organization Policy, ownership, waiver, or approval workflow;
- no automatic remediation;
- a human may recommend holding release, but that must not be represented as an
  AgentSec authorization or enforcement decision.

## Artifact and trust limits

- saved Manifests and reports are unsigned local files;
- SHA-256 checks internal consistency but not approver identity or freshness;
- output replacement is local and atomic but does not provide remote retention or
  access-control policy;
- secret redaction cannot recognize every proprietary or unlabeled secret;
- Capability evidence proves source declaration provenance, not runtime state;
- the workspace has no Git commit/tag/signature provenance.

## Product and release limits

- no SARIF, HTML, Web console, remote service, or package-index publication;
- no financial-loss estimate;
- 0.2.0 is accepted as a local internal MVP artifact;
- the Phase 1 and Phase 2 report families remain separate interfaces;
- future rule/risk/gate changes require independent version and ADR review.

# ADR-0055: SARIF 2.1.0 Reporter 0.1.0

- Status: Accepted
- Date: 2026-08-25
- Task: P2-25
- SARIF standard: `2.1.0`
- AgentSec SARIF Reporter: `0.1.0`

## Context

AgentSec already produces human-readable Text and strict AgentSec JSON reports,
but CI code-scanning systems commonly consume SARIF. P2-25 needs an interoperable
representation without allowing an output adapter to redefine risk, disclose
untrusted source text, or silently enable CI enforcement.

The reporter must cover three existing deterministic results:

```text
Phase 1 Assessment Findings
Capability Assessment Findings
P2-23 Overall Score
```

The current Config Schema freezes `output.format` to `text|json`, and the current
`scan` command has no safe artifact writer. P2-25 should not broaden those
contracts unnecessarily.

## Decision

1. Emit SARIF v2.1.0 with the OASIS Errata 01 schema URI.
2. Add strict immutable AgentSec SARIF subset models and deterministic
   `encode_sarif_json` / safe `decode_sarif_json` functions.
3. Require exactly one `run` per AgentSec SARIF document.
4. Map AgentSec Severity as follows:

   ```text
   Critical/High → error
   Medium        → warning
   Low           → note
   None          → none
   ```

5. Preserve Evidence Confidence as an independent AgentSec property; never use
   Confidence to reduce SARIF level.
6. Create one Rule descriptor per stable Rule ID and require every Result's
   `ruleId` and `ruleIndex` to resolve to the same descriptor.
7. Use versioned SARIF partial-fingerprint property names:

   ```text
   agentsecFindingId/v1
   agentsecOverallManifestSha256/v1
   ```

8. Emit URI-encoded project-relative locations with `%SRCROOT%` and line regions.
   Overall Score remains location-free because it is a management aggregation.
9. Preserve bounded AgentSec properties for score, Severity, Confidence,
   Correlation, related IDs, CVSS/CVE/CWE, Shadow/CVSS Gate state, Coverage, and
   version provenance.
10. Do not serialize Evidence excerpts, raw source values, Commands, URL values,
    Headers, environment values, credentials, tokens, or memory content.
11. Expose CLI SARIF only through explicit selectors:

    ```text
    agentsec scan --format sarif
    agentsec capability assess --format sarif
    ```

12. Keep Config Schema `output.format=text|json`; do not make SARIF a persistent
    project configuration value in P2-25.
13. Keep `scan` as stdout-only. Capability Assessment may use the existing safe
    writer with a required `.sarif` suffix and same-kind `--force` validation.
14. SARIF never changes CLI exit codes and never enables CI blocking. Incomplete
    analysis still emits a partial SARIF report and returns `2`.
15. Publish `OverallScoreSarifRenderer` as a Python API without inventing an
    Overall Score CLI in this task.
16. Version the AgentSec reporter independently as
    `SARIF_REPORTER_VERSION=0.1.0`; do not confuse it with the SARIF standard
    version `2.1.0`.

## Security boundaries

- Scanned projects, scripts, Hooks, Skills, Commands, Sub-Agents, and MCP servers
  are never executed or connected.
- SARIF messages cannot contain source excerpts or recognized secret values.
- Prompt-injection text remains untrusted data and is not copied to CI messages.
- Static declarations are never described as runtime capability or
  exploitability proof.
- `error` is a SARIF presentation level, not an AgentSec allow/block decision.
- Deterministic policy remains the only possible source of future CI authority.
- LLM output has no reporting or enforcement authority in P2-25.

## Consequences

### Positive

- Code-scanning consumers receive stable Rule identity, locations, fingerprints,
  Severity, Confidence, score, and version provenance.
- Phase 1 and Capability Findings share one safe SARIF vocabulary.
- Overall Score can be embedded in management-oriented SARIF workflows.
- Existing Text/JSON contracts, Config Schema, and exit semantics remain stable.
- Sensitive source content is not duplicated into a portable CI artifact.

### Trade-offs

- The P2-25 decoder validates an AgentSec SARIF subset, not every valid SARIF
  feature.
- The full third-party OASIS JSON Schema is not vendored or validated online.
- `scan` requires shell redirection instead of `--output`.
- Manifest, Diff, Impact, and Enforcement do not accept SARIF.
- P2-26 and later policy work must define blocking independently from SARIF
  `level`.
